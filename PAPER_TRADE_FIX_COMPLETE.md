## 🔧 What Was Fixed

### The Bug
**Location:** `core/paper_tracker.py` lines 313-350

**Old (Broken) Logic:**
```python
# LONG/UP position - profit when price goes up
if price_change_pct <= -stop_loss_pct:
    outcome = "STOPPED"  # ❌ Triggered during 6-48h period
    pnl_pct = -stop_loss_pct
elif price_change_pct >= take_profit_pct:
    outcome = "WIN"
    pnl_pct = take_profit_pct
```

**Problem:** Stop losses triggered **during** the 6-48 hour prediction window, marking predictions as "STOPPED" (losses) before they could be evaluated at the target time.

**Example Failure:**
- Prediction: "BTC DOWN in 48h" @ $195 (6-hour forecast)
- Hour 2: BTC at $205 (+5.1%) → **STOPPED** (marked as loss)
- Hour 6: BTC at $190 (-2.6%) → Prediction was **correct** but already marked as loss!

### The Fix
**New (Corrected) Logic:**
```python
# UP prediction: WIN if price went up at target time
if is_up_prediction:
    if price_change_pct > 0.01:  # Up more than 1%
        outcome = "WIN"
        pnl_pct = price_change_pct
    elif price_change_pct < -0.01:  # Down more than 1%
        outcome = "LOSS"
        pnl_pct = price_change_pct
    else:
        outcome = "BREAK_EVEN"
        pnl_pct = 0.0

# DOWN prediction: WIN if price went down at target time
elif is_down_prediction:
    if price_change_pct < -0.01:  # Down more than 1%
        outcome = "WIN"
        pnl_pct = abs(price_change_pct)  # Positive P&L
    elif price_change_pct > 0.01:  # Up more than 1%
        outcome = "LOSS"
        pnl_pct = -abs(price_change_pct)  # Negative P&L
```

**Key Changes:**
1. ✅ **Removed stop loss triggers during prediction window**
2. ✅ **Only evaluate at target time** (6h, 24h, or 48h)
3. ✅ **Simple binary: price went direction predicted = WIN, opposite = LOSS**
4. ✅ **1% threshold for BREAK_EVEN handling**

## 🎓 Lessons Learned

### 1. Stop Losses vs Prediction Evaluation
**Mistake:** Applied live trading stop loss logic to prediction accuracy evaluation

**Fix:** Separate concerns:
- **Live trading:** Stop losses protect capital (keep them)
- **Prediction accuracy:** Evaluate at target time (remove stop losses)

### 2. Model Bias vs Evaluation Logic
**Mistake:** Confused model bias (70% DOWN predictions) with evaluation failure (5.38% win rate)

**Reality:** Both were broken:
- Model bias → Fixed by retraining (47% UP now)
- Evaluation logic → Fixed by removing stop losses (16.7% win rate now)

### 3. Historical Data Contamination
**Insight:** Even with fixed evaluation, historical trades reflect old biased model

**Solution:** Track win rate **by date range**:
- Historical (all time): 16.7% (biased model + old eval)
- Recent (last 7 days): Expected 50-65% (balanced model + new eval)

### 4. Telegram Bot Discrepancy
**Root Cause:** Different evaluation criteria:
- Telegram: "Target price touched at any point"
- Database: "Price at target time"

**Solution:** Add both metrics:
- `touched_target` (for intraday trading)
- `closed_at_target` (for prediction accuracy)
